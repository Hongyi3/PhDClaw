# Governance

## Project model

ClawBio Scholar should operate as a maintainer-led open-source research software project with transparent decision making.

## Roles

### Lead Maintainer
Owns project vision, release decisions, scope control, and external scholarly positioning.

### Area Maintainers
Own specific domains such as:

- evidence and literature ingestion
- workflow and provenance
- manuscript and release tooling
- docs and community operations
- benchmarks and evaluation

### Contributors
Submit issues, pull requests, documentation, templates, and benchmark cases.

## Decision rules

- architecture decisions should be documented in `plans/documentation.md` and relevant docs
- significant scope changes require explicit maintainer approval
- release decisions should pass documented quality gates
- benchmark claims must be reproducible from public repo artifacts

## Release philosophy

Releases should prioritize stability, reproducibility, and scholarly credibility over feature volume.
